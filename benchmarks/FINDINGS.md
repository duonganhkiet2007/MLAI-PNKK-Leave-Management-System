# Confirmed evaluation findings

The comprehensive mock-inference run measured 810 real API submissions in 60 isolated batches across 1/5/10/15/20/30 concurrency and burst/staggered schedules. 25 requests remained unfinished at their 10-second completion deadline. The worker queue and application persistence race was subsequently reproduced by a deterministic regression test. Results use synthetic identities/documents and separate SQLite databases; production logic was not changed.

1. **Lost completion notification / request stuck PROCESSING.** Proof inspection can finish after submission reads PENDING but before the request is persisted. The worker then finds no waiting request; the newly saved request waits forever. Reproduce: `pytest benchmarks/tests/test_reliability.py::test_inspection_completion_before_pending_submit_persistence`. Relevant source: `backend/services/orchestration.py::process_new_request` and `backend/services/inspection_service.py::resume_pending_requests_for_proof`.
2. **Stale failure overwrites replacement proof state.** The success branch checks inspection version, while failure handling can reset a newer READY proof to PENDING. Test: `test_stale_failure_cannot_replace_current_proof`.
3. **Discarded stale job stays PROCESSING.** A version mismatch returns without settling the job. Test: `test_stale_job_not_left_processing`.
4. **Recovery misses applications whose proof already settled / exceeded retries.** Recovery marks/reset jobs but does not resume these waiting requests. Tests: `test_pending_application_recovery_after_restart`, `test_recovered_exhausted_job_resumes_request`. These are controlled recovery-method simulations, not a successful actual crash/restart claim.
5. **Disk cache ignores leave context.** Memory keys contain context, but disk names contain only file hash; a different leave-type prompt can reuse context-dependent output. Test: `test_cache_context_isolation`.
6. **Identity correlation accepts a conflicting synthetic subject.** Verified proof for Benchmark Person 999 was automatically accepted for Benchmark Person 000; shared tokens satisfy approximate matching. Test: `test_verified_medical_identity_match[Benchmark Person 999-NEED_CORRECTION]`. This evaluates policy correlation on injected verified fields, not real VLM extraction accuracy.
7. **Ambiguous reviewer text automatically approves.** Three authored ambiguous replies produced APPROVE_OVERRIDE. A conditional date correction became REQUEST_MORE_INFO. Cases: language-016/017/018/020. Default fallback is deterministic; these failures are not attributed to an LLM.
8. **Two-day medical leave bypasses documented manager escalation.** Boundary-008 produced AUTO_APPROVE where policy_rules.md §§3.1/3.4 require a manager. This is reported separately from policy-conflict cases excluded from accuracy.
9. **Raw model error content can reach logs and status responses.** Synthetic sentinel text was present in exception logs and the owner's proof status API. Tests: `test_failed_inspection_logs_do_not_expose_document_text`, `test_api_status_polling_does_not_disclose_sensitive_model_error`. This establishes error sanitization weaknesses, not unauthorized access to a real medical document.

Main report includes 169 passed, 14 failed and 25 skipped checks after appending the deterministic race regression. The 11 repeated framework utility checks passed and are not double-counted. Failed check counts are not incident counts or the number of distinct bugs. The independently labeled rule suite accuracy was 109/110 = 99.09%, excluding ten policy-conflict cases; this aggregate does not erase severe unsafe cases.

Not measured: real VLM/LLM quality or GPU latency; hard-kill backend recovery; branch coverage (coverage package unavailable); human final-resolution success rate; historical baseline-versus-optimized improvement.
